# Note to scout: jonasson2008-varma-878

The registered claim is mis-specified for a rerun outside MATLAB. Its ten `varma_llc` values come from `comparison.txt`, and that file's data are generated by `varma_sim`, which calls MATLAB's `randn` after `randn('state',1)`. On Octave 10.3.0 the same loop gives different data and different values (e.g. tinyAR -15.18 against the registered -12.62). The claim's "deterministic" label holds only for MATLAB.

I did not change the claim or its tolerance. The rerun is blocked.

Options for you to choose from:
1. Register the test data (the X matrices the loop generates) or the random stream as part of the claim, so the values are checked on the data themselves.
2. Register the claim as the Octave reproduction (values as produced by the authors' code on Octave), if that is what you want to measure.
3. Drop the claim and look for a paper with a non-random test.
