# jonasson2008-varma-878: blocked

**Verdict: blocked.** Basis: none (no result to grade).

The claim is ten `varma_llc` log-likelihood values printed in the shipped `Matlab/Tests/test/compare/comparison.txt` (TOMS 878, Jonasson and Ferrando). Each test case's data are generated by `varma_sim`, which draws from MATLAB's `randn` after `randn('state',1)`. This rerun ran on GNU Octave 10.3.0, whose `randn` stream differs, so the data differ and the values do not match.

(All ten are in `evidence/original-attempt.log` and the `VALUE` lines in `recipe.sh` output.)

## Why this is blocked, not not-reproduced

The registered values depend on a random stream the archive does not supply. Reproducing them needs either MATLAB itself, or the test data (the X each case generates). Neither is in the archive, and the claim does not state the generator. Reimplementing MATLAB's `randn` to make the numbers match would be tuning a missing input until the number fits, which `docs/method.md` forbids. So the claim, as registered, is mis-specified for a non-MATLAB rerun. See `note-to-scout.md`.

The Octave values are reproducible (the recipe run and the first attempt agree to all printed digits), but they do not test the registered claim.
